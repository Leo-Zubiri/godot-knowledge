- **Singletons (Autoload):** the scene system has no built-in place for data several scenes need (score, inventory); autoloads keep persistent data across scenes. Register under Project > Project Settings > Globals > Autoload with a name (becomes the node's `name`); with Enable checked (default) GDScript accesses it by that name. A scene autoload is added as a node; for a script the engine creates a Node with the script attached "before any other scenes are loaded". Entries are ordered with the arrows and read top to bottom; autoloads are children of `root` before the running scene, which is the last child of `root`. Godot does not enforce a true singleton (it can be instanced again). Never `free()`/`queue_free()` an autoload at runtime (crash). C#: Enable column has no effect; use a static `Instance` set in `_Ready()`. Scene-switching example: `_deferred_goto_scene.call_deferred(path)`; the deferred function frees `current_scene`, loads the new `PackedScene` with `ResourceLoader.load(path)`, `instantiate()`, `get_tree().root.add_child(...)` and optionally sets `get_tree().current_scene` for compatibility with `change_scene_to_file()`. Deleting the current scene from a signal callback is "a bad idea, because it may still be executing code".
- **SceneTree:** `change_scene_to_file(path)` → OK / `ERR_CANT_OPEN` / `ERR_CANT_CREATE`; `change_scene_to_packed(packed_scene)` → OK / `ERR_CANT_CREATE` / `ERR_INVALID_PARAMETER`; `reload_current_scene()`; `unload_current_scene()`. Timing: "the current scene node is immediately removed from the tree" (its `get_tree()` returns null and `current_scene` is null); at the end of the frame the old scene is freed and the new one added, so both never run at once; `await get_tree().scene_changed` to access the new scene reliably. `current_scene` is the root node of the loaded main scene (setting it directly does not add/remove nodes). `paused` stops 2D/3D physics and collision signals; process callbacks depend on each node's `process_mode`. `root` is the top Window; autoloads and the current scene are its children. `auto_accept_quit` default true; `quit(exit_code=0)` quits at the end of the iteration (not on iOS). Signals `scene_changed()`, `node_added(node)`, `node_removed(node)`.
- **Scene organization (best practice):** "you should design scenes to have no dependencies"; a higher-level API supplies dependencies of the lower level (dependency injection). Five ways a parent initialises a child: signals (child emits, parent connects — "only to respond to behavior, not start it"), a String method name the child calls with `call()`, a Callable property (safer: ownership of the method is unnecessary), a Node/Object reference (`$Child.target = self`), a NodePath (`$Child.target_path = ".."`). Siblings "should only be aware of their own hierarchies"; an ancestor mediates. Document external dependencies with `_get_configuration_warnings()` in a `@tool` script (warning icon in the Scene dock). Tree structure: a Main node (`main.gd` as primary controller) with a `World` (Node2D/Node3D) and a `GUI` (Control) child; levels are swapped as children of World (manual changes give full control over transitions); smaller games may use a "Game" singleton calling `SceneTree.change_scene_to_file()`; the GUI must be a singleton, a transitory part of the World, or a direct child of root or it is deleted on scene transitions. Autoload only a system that tracks its own data, is globally accessible and exists in isolation; systems that modify other systems belong in their own scripts/scenes, not autoloads. Parent-child only when removing the parent should remove the children; think of the SceneTree "in relational terms rather than spatial terms"; favour keeping data in-house (internal to a scene).
- **Engine:** `physics_ticks_per_second` default 60 (fixed iterations per second; controls physics simulation and `_physics_process()` rate; higher = more accurate for fast objects; below ~30 behaves poorly); `max_physics_steps_per_frame` default 8 (raise it when raising the tick rate well above default); `physics_jitter_fix` default 0.5 (0 or less = fully synchronised with real time; recommended 0 for custom interpolation or networked games; values above 2 discouraged); `max_fps` default 0 (uncapped; VSync takes precedence); `time_scale` default 1.0 (affects Timer, SceneTreeTimer and delta, not audio). Methods `get_physics_interpolation_fraction()`, `is_in_physics_frame()`, `get_frames_per_second()`, `get_physics_frames()`, `get_process_frames()`, `is_editor_hint()`, `register_singleton(name, instance)` / `has_singleton(name)` (mainly for plugins), `get_main_loop()`. The ProjectSettings page lists the same physics values under `physics/common/physics_ticks_per_second` (60), `physics/common/max_physics_steps_per_frame` (8), `physics/common/physics_jitter_fix` (0.5), `physics/common/physics_interpolation` (false), `physics/common/enable_object_picking` (true).
