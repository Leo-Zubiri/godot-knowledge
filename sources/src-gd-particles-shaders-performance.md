- **3D particle pages:** index lists creating a system, properties, process material, collision, sub-emitters, trails, turbulence, attractors, complex emission shapes. **Trails** work only in Forward+ and Mobile (not Compatibility): enable trail + lifetime, use `RibbonTrailMesh` or `TubeTrailMesh` in Draw Passes, enable "Use Particle Trails" in the material; tubes need Transform Align "Y to Velocity" or they flatten. **Attractors:** `GPUParticlesAttractorBox3D` (extents are half side lengths), `GPUParticlesAttractorSphere3D`, `GPUParticlesAttractorVectorField3D` (3D texture, UV Y flipped, neutral grey = no force); Strength (negative repels), Attenuation, Directionality, Cull Mask; the process material must enable attractor interaction; not implemented for 2D. **Collision:** GPU particles do not see the physics world; use `GPUParticlesCollisionBox3D`/`Sphere3D`/`HeightField3D` (runtime, no "room over room")/`SDF3D` (baked, static, Forward+/Mobile only); the system's visibility AABB must overlap the collider's (Generate Visibility AABB); thin colliders vs fast particles — thicken or raise Fixed FPS; `ParticleProcessMaterial.CollisionMode` DISABLED/RIGID/HIDE_ON_CONTACT. **Sub-emitters (search summary only, UNV wording):** assigned in the parent's `sub_emitter`, which then stops emitting on its own; self-reference does not spawn; modes on the process material `SubEmitterMode` DISABLED/CONSTANT/AT_END/AT_COLLISION/AT_START; active sub-particles capped by the sub-emitter's own Amount; Explosiveness has no effect; `emit_subparticle()` is the only custom function supported.
- **GPUParticles3D class:** `amount` (default 8), `amount_ratio` (no restart; lowering it does not improve performance), `lifetime`, `one_shot`, `preprocess` (expensive when high), `explosiveness`, `randomness`, `fixed_fps`, `interpolate`, `fract_delta`, `local_coords`, `draw_order`, `visibility_aabb`, `sub_emitter`, `trail_enabled`; `restart(keep_seed)`, `emit_particle(...)` (Forward+/Mobile only), `capture_aabb()`; for one-shot restart call `restart()`; `DRAW_ORDER_INDEX` is the only order supporting motion vectors. **ParticleProcessMaterial (4.7):** `EmissionShape` POINT/SPHERE/SPHERE_SURFACE/BOX/POINTS/DIRECTED_POINTS/RING; 3D particles collide only with `GPUParticlesCollision3D` nodes; colour properties multiply vertex colours so a `BaseMaterial3D` needs `vertex_color_use_as_albedo`; first 100,000 characters read only.
- **Visual shaders (search summary, UNV):** `Shader` of type `VisualShader` in a `ShaderMaterial`; graph converts to script shader (code viewable); Expression node; Group node in latest docs; limits not read. **Shader pages index:** introduction, shading reference, your first shader, visual shaders, compute shaders, screen-reading, converting GLSL, shaders style guide, SubViewport as texture, custom/advanced post-processing, making trees. **Shaders style guide:** LF, tabs, UTF-8 no BOM, 1TBS braces, lines < 100 characters, `rgba` for colours and `xyzw` otherwise, snake_case, CONSTANT_CASE constants, uppercase unindented preprocessor directives; declaration order shader type, render mode, docstring, uniforms, constants, varyings, functions, then `vertex()`, `fragment()`, `light()`; no performance guidance; default clang-format does not match (a provided `.clang-format` is needed).
- **Pipeline compilations (compile stutter):** two stages — shader compilation and driver pipeline compilation (driver cache usually cleared on driver updates); ubershaders and specialization constants cut pipeline counts; **ahead-of-time pipeline precompilation from 4.4** while meshes/nodes load (2D canvas pipelines not precompiled); pipeline monitors report Canvas, Mesh, Surface, Draw and Specialization steps (rising Surface/Draw mid-gameplay points to stutter); advice: enable features early with a simple scene, avoid changing MSAA or shadow depth precision mid-game, keep a hidden instance of dynamically spawned effects. **Shader Baker (4.5+):** export option stores compiled intermediate shaders in the PCK; shortens first launch, does not remove stutter; Forward+ and Mobile only, not web or headless exports, must match `rendering/rendering_device/driver`. Compatibility renderer: ubershaders/precompilation do not apply; workaround is to show materials/particles in view for at least one frame during loading.
- **CPU optimization:** profile first (built-in profiler started manually, external profilers, `Time.get_ticks_usec()` averaged over many runs); GDScript prioritizes ease over speed; C# can pause for garbage collection (use pooling); fewer nodes with more work each tends to be faster; simplified collision shapes; lowering the physics tick rate causes jitter and input lag (built-in physics interpolation smooths cheaply); threads without guarded shared memory race; pausing or hiding nodes can be slower than `remove_child()`; the profiler may omit time waiting on servers (known bug). **GPU optimization:** fewer, grouped draw calls (2D batching; merge static 3D meshes, merged objects cannot be culled individually); reuse materials first, shaders second; vertex count rarely the desktop bottleneck; test fill rate by comparing FPS at large vs small window with V-Sync off; VRAM compression usually fine in 3D, more visible in 2D, pixel art keeps it disabled, many Android devices do not support compression for textures with transparency; shadows and post-processing are major fragment costs; mobile GPUs are tile-based so viewport textures and some post-processing cost more.
- **Servers:** RenderingServer, PhysicsServer2D/3D, AudioServer are low-level APIs; RIDs are opaque, manually freed and not reference-counted (keep the resource alive elsewhere); use only after other optimizations (tens of thousands of instances per frame); reading values from servers stalls them; canvas item primitives cannot be modified once added; reset physics interpolation on the first frame for RenderingServer-created items. **Thread-safe APIs:** most global singletons are thread-safe, but physics needs "Run on Separate Thread" and rendering "Thread Model: Separate" (known bugs); the active scene tree is not thread-safe — build hierarchies off-tree and attach on the main thread via `call_deferred`; do not modify one resource from several threads; GDScript containers allow reading/writing existing elements but resizing or add/remove needs a mutex.
