- **App Store Server API:** "a REST API that you call from your server to request and provide information about your customers' In-App Purchases." Endpoints named: Get Transaction Info ("single transactions"), Get Transaction History, Get All Subscription Statuses, Get Refund History, Send Consumption Information ("after you receive the `CONSUMPTION_REQUEST` notificationType"), Look Up Order ID (from the customer's e-mail receipt; not available in sandbox), Get App Transaction Info, Set App Account Token ("Sets the app account token value for a purchase the customer makes outside of your app, or updates its value"). "The App Store signs the transaction and subscription renewal information that this API returns using the JSON Web Signature (JWS) specification." Auth: "Calls to the API require JSON Web Tokens (JWTs) for authorization; you obtain keys to create the tokens from your organization's App Store Connect account" — sent as a bearer token. Sandbox base URL `https://api.storekit-sandbox.apple.com/` ("`/inApps` in the path is case-sensitive"); production URL not in the text read. Environment detection: call production, on error `4040010` (TransactionIdNotFoundError) call sandbox; `environment` is also in `JWSTransactionDecodedPayload`.
- **App Store Server Notifications:** "a server-to-server service that sends real-time notifications for In-App Purchase events"; "Your server is responsible for parsing, interpreting, and responding to all server-to-server notification posts"; enable by providing an HTTPS URL in App Store Connect, opting in separately for production and sandbox. "The App Store Server Notifications V1 endpoint and version 1 notifications, notification_type, are deprecated. Implement the App Store Server Notifications V2 endpoint". Test with Request a Test Notification → `TEST` type. `EXTERNAL_PURCHASE_TOKEN` applies to apps using external purchase APIs.
- **`notificationType` (V2) — descriptions:** `ONE_TIME_CHARGE` "the customer purchased a consumable, non-consumable, or non-renewing subscription"; `SUBSCRIBED` (subtypes `INITIAL_BUY`, `RESUBSCRIBE`); `DID_RENEW` (subtype `BILLING_RECOVERY`); `DID_FAIL_TO_RENEW` (subtype `GRACE_PERIOD`; billing retried "for 60 days"); `EXPIRED` (subtypes `VOLUNTARY`, `BILLING_RETRY`, `PRICE_INCREASE`, `PRODUCT_NOT_FOR_SALE`); `GRACE_PERIOD_EXPIRED`; **`REFUND`** "the App Store successfully refunded a transaction for a consumable In-App Purchase, a non-consumable In-App Purchase, an auto-renewable subscription, or a non-renewing subscription" with `revocationDate`, `originalTransactionId`, `productId`, `revocationReason`; `REFUND_DECLINED`; **`REFUND_REVERSED`** "the App Store reversed a previously granted refund due to a dispute … If your app revoked content or services as a result of the related refund, it needs to reinstate them"; **`REVOKE`** — an entitlement obtained through Family Sharing or an organization/group "is no longer available" (purchaser disabled sharing, left the family, or received a refund); **`CONSUMPTION_REQUEST`** "the customer initiated a refund request for a consumable In-App Purchase or auto-renewable subscription, and the App Store is requesting that you provide consumption data"; also `DID_CHANGE_RENEWAL_PREF/STATUS`, `OFFER_REDEEMED`, `PRICE_INCREASE`, `RENEWAL_EXTENDED/EXTENSION`, `RESCIND_CONSENT`, `UNCLAIM_SEATS`, `METADATA_UPDATE`, `MIGRATION`, `PRICE_CHANGE`, `TEST`.
- **App Store Receipts / verifyReceipt:** "Receipts are deprecated. To validate In-App Purchases on your server without using receipts, call the App Store Server API to get Apple-signed transaction and subscription information for your customers, or verify the AppTransaction and Transaction signed data that your app obtains. You can also get the same signed transaction and subscription information from the App Store Server Notifications V2 endpoint." "The verifyReceipt endpoint is deprecated." Its description: "Your server can access the verifyReceipt endpoint to validate app and in-app transaction receipts. Submit a receipt to the App Store with your shared secret to receive a JSON response". The page did not contain a device-side warning (*not on the page read*); endpoint URLs and status codes were not read (*unverified*).
- **App Store Review Guidelines 3.1.1 In-App Purchase (as written 2026-11-08):** "If you want to unlock features or functionality within your app, (by way of example: subscriptions, in-game currencies, game levels, access to premium content, or unlocking a full version), you must use in-app purchase. Apps may not use their own mechanisms to unlock content or functionality, such as license keys, augmented reality markers, QR codes, cryptocurrencies and cryptocurrency wallets, etc."; "Any credits or in-game currencies purchased via in-app purchase may not expire, and you should make sure you have a restore mechanism for any restorable in-app purchases."; gifts "may only be refunded to the original purchaser"; "Apps offering 'loot boxes' or other mechanisms that provide randomized virtual items for purchase must disclose the odds of receiving each type of item to customers prior to purchase."; free trials via a Price Tier 0 non-consumable named "XX-day Trial". 3.1.2 subscriptions must provide ongoing value, last ≥ 7 days, be available across the user's devices; 3.1.3 lists exceptions (reader apps, multiplatform services, enterprise, person-to-person, physical goods, companion apps, advertising management) with US-storefront carve-outs. The phrase "available to all of the user's devices" appears in the subscription section, not in 3.1.1.
