- **Index:** export pages — exporting projects; packs, patches and mods; feature tags; Windows; Linux; macOS; Android; iOS; visionOS; Web; manual Windows icon; running Godot apps on macOS; Android Gradle builds; one-click deploy; dedicated servers. **No CI page, no console page and no encryption page** in the index.
- **Presets/templates:** presets in the Export dialog (Export All / Export Project / Export PCK/ZIP); templates (and some SDKs) must be installed first via Editor > Manage Export Templates. Resource filter modes: all, selected scenes, selected resources, all except checked, dedicated server; extra filters for non-resource files and excludes. `export_presets.cfg` is safe to commit; `.godot/export_credentials.cfg` holds passwords/keys and must stay out of VCS (copy manually to a new machine). Output paths are relative to the project folder; files/folders starting with a period are never exported; missing templates/SDKs block export.
- **PCK/patches/DLC:** PCK is uncompressed, faster, default; ZIP smaller and slower (an exported binary does not auto-load a ZIP pack — launcher script needed). `--export-pack` writes `.pck`/`.zip`; `ProjectSettings.load_resource_pack()` loads them and a pack replaces an existing file at the same path by default (second argument `false` opts out). Patching: add the original release PCK as a base pack in the Patching tab, enable "Export as Patch", add each later patch to the base packs; load order matters; delta patches are smaller but load slower and re-exporting can be non-deterministic (breaks delta patches, not regular ones). Load packs early (e.g. autoload `_init()`); path collisions silently overwrite (put mods in their own folder); C# needs `Assembly.LoadFile` before loading. No built-in DRM; the page suggests signing packs with the Crypto class for launcher-based patching.
- **Dedicated servers:** "Export as dedicated server" resource filter adds the `dedicated_server` tag (resources Strip Visuals/Keep/Remove); an export template binary is recommended over the editor binary; no CI content.
- **Encryption (search summary only, UNV on exact wording):** generate a 256-bit AES key, build export templates from source with `SCRIPT_AES256_ENCRYPTION_KEY`, set the same key in the preset's Encryption tab; command-line export uses `GODOT_SCRIPT_ENCRYPTION_KEY`; a runtime MD5/`ERR_FILE_CORRUPT` error usually means the key was not compiled in; a 4.4 version says it does not work with official precompiled templates; Android keeps assets in the APK so PCK encryption needs APK expansion.
- **Command-line export (exporting_projects, 4.7):** `--export-release`, `--export-debug`, `--export-pack` with a preset name and output path; the preset must already exist; quote names with spaces; `--path` runs outside the project folder. The section does not mention `--headless`, template locations, `--export-patch`, exit codes or CI (the CLI tutorial, preserved earlier, says `--headless` is required for export on GPU-less CI). No official CI or GitHub Actions page found; how CI runners obtain templates is not documented (UNV).
- **Windows:** x86_64 default, x86_32 not advised, arm64 will not run on x86_64 Windows; embedded PCK limit ≈3.75 GB (executable+PCK ≈3.89 GB); signing needs Windows SDK or `osslsigncode` plus a certificate; environment variables override export menu values. **Linux:** seven architectures listed (x86_64, x86_32, arm64, arm32, rv64, ppc64, loongarch64); no official templates for rv64/ppc64/loongarch64; glibc compatibility, PCK embedding and Flatpak not discussed. **macOS:** Universal 2 `.app`; signing and notarization (`codesign`/`notarytool` on macOS, `rcodesign` elsewhere; DMG needs macOS; Apple ID or API credentials, not both; Debugging entitlement must be off for notarization; an `.app` exported from Windows loses its executable flag — `chmod +x`).
- **Android:** needs a JDK (OpenJDK 17 recommended), Android SDK (Platform-Tools 35.0.0+, Build-Tools 35.0.1, Platform 35, Command-line Tools, CMake 3.10.2.4988404, NDK r28b; not a distro-packaged SDK); release keystore via `keytool` (keystore and key passwords must currently match); environment variables `GODOT_ANDROID_KEYSTORE_RELEASE_PATH/_USER/_PASSWORD` and `_DEBUG_*`; Google Play needs an AAB, which requires the Gradle build and a non-debug keystore; C# experimental since 4.2; target SDK, architectures and CLI export not covered. **Gradle build:** install the template from the Project menu (creates `res://android/build`); folders starting with an underscore are left out of the APK. **iOS:** export must run on macOS with Xcode; output is an Xcode project; needs a 10-character Team ID and unique Bundle Identifier; the simulator supports only Compatibility; C# experimental.
- **Web:** single-threaded export is the default since 4.3 and needs no special headers; threads need SharedArrayBuffer, hence HTTPS plus `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (a PWA service worker can simulate them); only WebGL 2.0 (Compatibility); serve `.wasm` as `application/wasm` and compress it (hosts without on-the-fly compression, such as itch.io, need precompressed `.pck`/`.wasm`); audio autoplay, fullscreen and cursor capture need an input event; `user://` persistence depends on cookies/IndexedDB; networking limited to HTTP, WebSocket, WebRTC; **Godot 4 C# projects cannot export to the web**; do not edit generated HTML (use a Custom HTML shell); main file `index.html`; Safari has WebGL 2 issues. visionOS and consoles: no page read / no console statement found.
- **One-click deploy:** Android and iOS run on a connected device with debugging, desktop over SSH, Web via a local server; a preset must be marked Runnable (one per platform); a service-worker cache can show an old project in the browser.
- **Feature tags (4.7):** check with `OS.has_feature(name)`; defaults include `windows`, `linux`, `android`, `web`, `debug`, `release`, `editor`, `template`, `x86_64`, `arm64`, `64`, `32`, `double`, `single`, `threads`, `nothreads`, `etc2`, `s3tc`; case-sensitive; texture-compression tags, `web_<platform>` and `movie` are not constant at runtime; `mobile` stays false in a Web export on a phone (use `web_android`/`web_ios`); custom tags apply only to exported builds; per-feature setting overrides use `setting.feature` keys — `ProjectSettings.get_setting` ignores them (use `get_setting_with_override`). **Engine (4.7):** `Engine.get_version_info()` keys `major`, `minor`, `patch`, `hex`, `status`, `build`, `hash`, `timestamp`, `string`; `Engine.is_editor_hint()` vs `OS.has_feature("editor")`. `application/config/version` exists (default empty).
