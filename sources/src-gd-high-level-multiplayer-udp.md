- **High-level multiplayer:** every node has a `multiplayer` property (a `MultiplayerAPI`); by default all nodes share one; a `MultiplayerAPI` can be assigned to a node path (server and client in one instance). `MultiplayerPeer` implementations: ENet, WebRTC, WebSocket. The **server's unique ID is always 1**; clients get random positive integers; `multiplayer.is_server()`, `multiplayer.get_unique_id()`. Client: `ENetMultiplayerPeer.new().create_client(address, port)` then assign to `multiplayer.multiplayer_peer`; server: `create_server(port, max_clients)`. Assign `OfflineMultiplayerPeer` to stop. Signals on all peers: `peer_connected(id)`, `peer_disconnected(id)`; clients only: `connected_to_server()`, `connection_failed()`, `server_disconnected()`. **RPC:** annotate with `@rpc`; call on all peers with `f.rpc()`, on one with `f.rpc_id(id)`. Default `@rpc("authority", "call_remote", "reliable", 0)`; mode `"authority"` (only the node's multiplayer authority may call it remotely) or `"any_peer"`; sync `"call_remote"`/`"call_local"`; transfer `"reliable"`, `"unreliable"`, `"unreliable_ordered"`; channel last. `multiplayer.get_remote_sender_id()` inside an RPC. Sender and receiver need the same `NodePath` — use `add_child(node, true)` (readable names) for RPC nodes. RPC declarations must match on both sides; arguments are not type-checked; RPCs only on `Node`-derived classes; Objects/Callables are not serialised. Channel 0 is three channels (one per transfer mode); separate variable-size packets into their own channels. Authority defaults to the server; `Node.set_multiplayer_authority()` changes it per node. **Hosting:** LAN clients use the host's internal IP (usually 192.168.x.x); the API uses UDP only (forward UDP, not TCP); modified ENet with IPv6. **Authentication:** `auth_callback`, `auth_timeout`, `send_auth()`, `complete_auth(peer_id)`, `peer_authenticating`. **Security:** treat all client input as untrusted; keep the server authoritative for positions, combat, inventory and outcomes; validate RPC arguments; rate-limit; "send player input or movement intent to the server, then validate and apply it there". Example lobby autoload: port 7000, max 20, `_register_player` as `any_peer`/`reliable`, `load_game` `call_local`, `player_loaded` `any_peer`/`call_local` counted by the server, `Lobby.player_loaded.rpc_id(1)` from the game scene's `_ready()`.
- **ENetMultiplayerPeer:** `create_server(port, max_clients=32, max_channels=0, in_bandwidth=0, out_bandwidth=0)` — max_clients up to 4095; binds all interfaces unless `set_bind_ip()`; ports < 1024 may need elevated permissions. `create_client(address, port, channel_count=0, in_bandwidth=0, out_bandwidth=0, local_port=0)`. `create_mesh(unique_id)` + `add_mesh_peer()`. `get_peer(id)`, `host`. Returns `ERR_ALREADY_IN_USE` if a connection is open (call `close()` first), `ERR_CANT_CREATE` on failure. ENet is UDP only; `UPNP` can try to forward the port.
- **MultiplayerSynchronizer:** replicates properties listed in `replication_config` from the multiplayer authority to remote peers; `replication_interval` (0 = every network process frame, for `REPLICATION_MODE_ALWAYS`), `delta_interval` (for `REPLICATION_MODE_ON_CHANGE`), `root_path` (default `..`), `public_visibility` = true, `visibility_update_mode` (`VISIBILITY_PROCESS_IDLE` 0, `VISIBILITY_PROCESS_PHYSICS` 1, `VISIBILITY_PROCESS_NONE` 2); `add_visibility_filter(Callable)`, `set_visibility_for(peer, visible)` (peer 0 = public), `update_visibility()`, `get_visibility_for()`. Signals `synchronized`, `delta_synchronized`, `visibility_changed(for_peer)`. Spawners honour synchronizer visibility when the `root_path` node was spawned by one. **Not supported:** Object-type properties (e.g. Resource), peer-specific values (instance IDs, RIDs).
- **SceneReplicationConfig:** `REPLICATION_MODE_NEVER` 0, `REPLICATION_MODE_ALWAYS` 1 ("constantly sending updates using unreliable transfer mode"), `REPLICATION_MODE_ON_CHANGE` 2 ("reliable transfer mode when its value changes"); `add_property(path)`, `property_set_spawn(path, enabled)` (sync on spawn), `property_set_replication_mode(path, mode)`; `property_set_watch` deprecated in favour of ON_CHANGE.
- **MultiplayerSpawner:** replicates nodes from the authority to other peers: scenes listed with `add_spawnable_scene(path)` and added as direct children of `spawn_path` are replicated automatically; `spawn(data)` runs `spawn_function` on all peers (must return a node not yet in the tree; the spawner adds it); `spawn_limit` (0 = none); signals `spawned(node)`/`despawned(node)` only on remote peers; `clear_spawnable_scenes()` does not despawn existing instances.
- **PacketPeerUDP:** "send and receive raw UDP packets as well as Variants". `bind(port, bind_address="*", recv_buf_size=65536)` (`"*"` = all IPv4+IPv6 addresses); `set_broadcast_enabled(enabled)` — disabled by default and **must be enabled before sending to a broadcast address such as 255.255.255.255**; `set_dest_address(host, port)`; `connect_to_host(host, port)` filters to one peer, sends nothing and does not protect against IP spoofing; `get_packet_ip()`/`get_packet_port()` give the last sender; `join_multicast_group(address, interface)` (list interfaces with `IP.get_local_interfaces()`); `wait()` blocks and cannot be interrupted (use a "death pill" packet); `is_bound()`, `is_socket_connected()`, `close()`. **Android:** enable the `INTERNET` permission in the export preset or all networking is blocked; some devices need `CHANGE_WIFI_MULTICAST_STATE` for multicast/broadcast, and receiving broadcasts may also require `set_broadcast_enabled(true)`. Use TLS/DTLS for sensitive data.
