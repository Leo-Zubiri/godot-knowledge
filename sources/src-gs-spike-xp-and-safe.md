# Source — "Spike" in Extreme Programming / SAFe (paraphrased)

Facts gathered by web search on 2026-11-10; pages named below were seen as search-result summaries, not full fetches —
treat as `paraphrased`, re-fetch to promote.

- **Origin (XP):** the term is credited to **Kent Beck** — "drive a spike through the entire design", a thin vertical
  path that tests technical feasibility. The XP rule page defines a **spike solution** as "a very simple program to
  explore potential solutions." (person.dibris.unige.it XP rules / spike.html)
- **Purpose:** **reduce risk** — resolve a technical problem or **increase the reliability of a user story's estimate**.
  It is **time-boxed**. (agilepainrelief glossary; SAFe "Spikes")
- **Throwaway:** spike code is **disposable** — "written fast, without worrying about code quality"; it exists **to
  learn, not to ship**. (multiple glossaries)
- **Contrast — tracer bullet:** a spike is a basic **throwaway** implementation to learn about the problem space; a
  **tracer bullet** is end-to-end code **meant to be kept**. (Amplitude project-planning article)
- **Not only code:** SAFe formalizes spikes as an **Enabler Story** type; broader modern usage includes vendor
  evaluation, user research, or a feasibility check. (scaledagileframework.com/spikes)
